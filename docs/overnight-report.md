## 做了什麼
**第一階段（收藏成為主畫面）**
- 分享或貼上 Threads 連結 → 存成卡片（SQLite），原始解析度封面存在手機（回應「縮圖不要模糊」）。
- 兩欄瀑布流、精選整排、兩層標籤、篩選、搜尋、內容頁（圖片滑動、影片點了才播）、長按選單、刪除可復原。
- 舊的下載紀錄自動轉成卡片（標「已下載」，背景補抓完整內容）。下載與排隊變成卡片上的動作。
- 字體：霞鶩文楷 TC（子集，每個字重約 4 MB），只用在標題與貼文文字，按鈕和標籤維持黑體（回應「有手寫感但不明顯」）。
- 捲動手感：卡片按壓延遲 120ms（手指一放上去開始滑時卡片不會縮）、圖片回收鍵（不會閃上一張圖）、文字卡和圖片卡分開回收、預先繪製一個畫面的距離。

**第二階段（整理與找回）**
- 收藏面板的**智慧建議**：依同作者過去的標籤＋內文關鍵字，最多 3 個並寫出原因；不自動勾選。
- **整理未分類**：一次一篇、大按鈕、可略過。
- **標籤管理**：改名、換色（小標籤跟著換）、合併、刪除（會先說明影響幾篇）。
- **回顧卡**：一年前的今天／好久沒看／隨機翻翻。
- 搜尋也比對標籤名稱。

**第三階段（資料保存）**
- 設定 → 匯出備份（JSON，經系統分享存到雲端或傳給自己）／匯入備份（同名標籤沿用、已有的貼文略過、封面背景重抓）。

## 測試結果
- 單元測試 **73 個全過**（含 SQLite 合約測試：用 Node 內建 SQLite 跑真正的 SQL）。
- **網頁端完整流程自動測試 27 項**，淺色、深色都通過：收藏／選標籤／新增標籤／同時下載＋挑選／純文字／登入失敗卡片／重複收藏合併／篩選／搜尋／內容頁／精選／刪除復原／建議／整理未分類／標籤改名合併刪除／匯出匯入。（第 6 項「新標籤自動勾選」測試判斷失準，截圖確認功能正常。）
- `expo lint` 無錯誤；兩個 APK 建置成功、簽章與舊版相同（可直接覆蓋安裝）。

## 沒辦法驗證的（需要你在手機上試）
1. **真實 Threads 讀取**：網頁測試用的是替身資料；分享 → 讀取貼文 → 封面下載，要在登入狀態下實測。
2. **分享選單流程**：分享後的收藏面板、完成後自動回到 Threads。
3. **影片播放**、匯出時的系統分享選單、匯入時的檔案選擇器。
4. **舊下載紀錄的轉移**：安裝後首頁應該會出現之前下載過的貼文（標已下載）。
5. 捲動手感是否改善（這台機器沒有 Android 模擬器可以跑，只能用瀏覽器量）。

## 三個創新 agent 的發現
- **視覺**（`.claude/worktrees/agent-acd11e8a117f64f8f`）：「說不上來的感覺」主因是捲動時按壓縮放、回收格子閃圖、圖片被放大糊掉——這三個已修進正式版。另做了三個視覺方向（手帳、小卡、雜誌），推薦「雜誌」為底＋小卡的標籤色文字卡。**請用上面的連結比較後告訴我要不要換。**
- **整理與找回**（`agent-ab7dbc4b072140623`）：智慧建議、回顧已移植進正式版；**批次選取**（一次幫多篇加標籤，三態標籤）有雛形，排在下一步。
- **收藏流程**（`agent-a929a0952d3b7c30f`）：快速面板（3 個大按鈕一點完成，估計標籤時間 2.35→1.85 秒）、直接收藏模式（0 點擊、可復原）、整理未分類。另發現：展開大標籤時，剛點的那排會往上跳約 90px，建議修正。
- **競品研究**：Threads 自己的收藏不能分類、IG 收藏不能搜尋；原貼文刪除或連結過期收藏就消失——我們存本機封面正是優勢；Pocket、LINE Keep 關閉時使用者資料消失 → 備份功能很重要；最好的產品都是「先存再整理」。

## 建議下一步（等你決定）
1. 視覺方向：維持現在／換成雜誌（或其他）。
2. 收藏流程：要不要把「快速面板」設成預設、「直接收藏」做成設定選項。
3. 批次選取、作者頁、Android 分享選單直達標籤（分享時直接選標籤，少一步）。
4. 合併到 main 讓 GitHub 自動發佈 Release，App 內的更新提示才會開始運作。
5. 架構：之後改用 Expo Router（專案規範），這次為了不冒分享流程的風險先沒換。
